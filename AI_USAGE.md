# Использование Codex — фактический отчёт

Дата финальной сверки: 4 ноября 2026 года. Источник требований: страницы 3–4 LD_LATTE_test_automation.pdf и пользовательское ТЗ. AI-инструмент — Codex; субагенты и генерация изображений не использовались.

## Что выполнено

Codex спроектировал и написал React/TypeScript/Vite-приложение, Supabase Auth и Data API, защищённые маршруты, формы заявок, статусы, поиск/фильтр, адаптивный русский интерфейс, SQL-миграцию и проверки. Подготовил существующие документы сдачи и размещение на Sites. Дизайн и архитектура при финальной приёмке не менялись.

Пользователь создал Supabase-проект, применил схему и сообщил о трёх RLS-политиках; Codex не запускал миграцию повторно. Пользователь настроил публичный ключ и самостоятельно зарегистрировал/подтвердил аккаунты A/B. Пароли вводились только локально.

Решения: Supabase — источник реальных данных; владелец/UUID/начальный статус/даты назначаются БД; UPDATE ограничен колонками и RLS; RHF/Zod валидируют поля; синхронный ref-замок предотвращает параллельные отправки; после сохранения список перечитывается. Обычный CSS выбран вместо Tailwind для небольшого интерфейса. Поиск выполняется над разрешёнными строками.

Проверены все текущие отслеживаемые файлы и вся локальная история Git: секретные шаблоны и фактические пароли A/B не найдены; env-файлы с паролями, сборки и тестовые артефакты не отслеживаются. Сборка также проверена на secret key и тестовые пароли.

## Возникшие проблемы и решения

1. Песочница блокировала DNS/localhost и временные операции Vitest. Для необходимых установок и проверок использован механизм разрешений среды.
2. Первый аудит зависимостей: 14 уязвимостей, включая 2 critical. Обновлены инструменты разработки, minimatch закреплён на исправленной ветке. Vitest latest не подходил Node 25, установлен 4.1.12. Повторный аудит сообщил 0.
3. Линтер потребовал const вместо let в тестовой ссылке.
4. Для Playwright установлен отсутствовавший Chromium.
5. Два E2E-селектора уточнены: Новая встречалась также в option, а status — у загрузки и уведомления. После исправления 6 тестов прошли.
6. SQL-проверка обязательных строк усилена для пробелов, табуляций и переносов.
7. Ошибка кавычек вспомогательного node -e не внесла изменений; исправление выполнено патчем.
8. Supabase MCP возвращает Unknown tool. Настройка выполнена пользователем, реальная проверка проведена JS SDK/API; доступ к pg_class через MCP не получен.
9. Автоматизация Edge останавливалась из-за невозможности надёжно определить URL. Production CRUD проверял пользователь; публичную регистрацию и ширину проверил доступный браузерный инструмент.
10. Первый шаг передачи данных публикации был отклонён в подтверждении; после отдельного разрешения повторён успешно.
11. Сборка сообщает предупреждения стороннего Zod и о размере JS-чанка более 500 kB; ошибок сборки нет.

## Подготовка Amvera после проверки доступа из РФ

Пользователь подтвердил все оставшиеся production-сценарии, но сообщил об отказе без VPN. Globalping: три RU-узла дали HTTP 403, DE — 200; два RU-запроса к Supabase дали штатный 401 без API-ключа. Причина локализована на защитном слое chatgpt.site, точное внутреннее правило недоступно.

Документация Amvera показала отсутствие env панели на этапе сборки. Добавлены amvera.yaml, статический сервер стандартной библиотеки Node.js и публичная runtime-конфигурация перед SDK. Никаких серверных бизнес-методов, изменений Auth/RLS, схемы, форм или дизайна не добавлено. Секретные ключи сервер не принимает; в браузер попадают только URL и публичный ключ.

Фактически повторно прошли TypeScript, ESLint, сборка с пустыми VITE-параметрами, 8 unit/component, 2 новых HTTP/config-теста и 6 E2E с подменой Supabase. В bundle нет URL/ключа текущего проекта, runtime-механизм присутствует. Подготовка отправлена в GitHub коммитом 823e55d. Затем пользователь создал отдельный проект Amvera, выбрал «Начальный плюс» и выполнил push и сборку. Снимок панели подтвердил запуск сервера на порту 80; старый сайт и другие проекты пользователя не изменялись.

Дополнительная проверка сборки с runtime-конфигурацией браузером на localhost:5180 не выполнена: разрешение на сетевой доступ браузера к этому origin было отклонено. Обходные способы не использовались. Временный сервер остановлен. Впоследствии работу опубликованной runtime-конфигурации в браузере подтвердил пользователь на Amvera.

## Проверка опубликованной версии при потере соединения

По дополнительному запросу пользователя выполнен отдельный Playwright-прогон опубликованной Amvera с настоящим Supabase. Первый запуск остановился до сохранения из-за слишком точного селектора категории (не учтена звёздочка обязательного поля); исправлен только локальный тестовый сценарий. Повторный запуск 4 ноября 2026 года в 19:37 UTC завершился PASS, код 0.

Сеть отключалась через context.setOffline только у тестового браузера, без подмены HTTP-ответов. Проверены создание и редактирование: реальная транспортная ошибка, понятное сообщение, сохранение полей, отсутствие ложного успеха, разблокировка формы и отсутствие изменений в базе. После восстановления сети настоящий API подтвердил создание 201 и изменение 200; ровно одна заявка сохранила данные после обновления. Тестовая запись de3a2340-dddc-44f3-8dbe-e1d2a995631a оставлена для осмотра. Реальный HTTP 500 не провоцировался.

Результат и два снимка формы находятся локально в test-results/production-network/; сценарий — test-results/production-network-check.mjs. Они исключены из Git. Использованы локальные данные тестового аккаунта, без вывода паролей. Приложение, схема и публикация не менялись. По явному запросу пользователя результаты синхронизируются с GitHub отдельным коммитом только ACCEPTANCE.md и AI_USAGE.md, без отправки в Amvera и повторной сборки.
