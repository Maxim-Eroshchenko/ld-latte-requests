## Защита Supabase

Ранее npm run test:rls фактически завершился с PASS и кодом 0: A/B читают и меняют свои заявки; прямой чужой SELECT/UPDATE не даёт доступа; подмена user_id при INSERT/UPDATE запрещена; Новая назначается при создании; недопустимые поля и анонимный доступ отклоняются. Проверка не повторялась без причины.

Отдельный запрос pg_class для relrowsecurity/relforcerowsecurity через Supabase MCP вернул Unknown tool. Флаг не прочитан Codex напрямую; включение RLS сообщено пользователем, а реальное поведение изоляции подтверждено API. В исходной миграции RLS включён и forced.

В текущих файлах и всей доступной истории Git не найдены секретные токены, service_role JWT, приватные ключи и фактические пароли тестовых A/B. .env.local/.env.rls и артефакты не отслеживаются. В production-сборке не найдены secret key и пароли A/B. Публичный Supabase publishable key допустим в браузере.

## Доступ и маршруты

После разрешения владельца Sites access_mode = public; GitHub visibility = public. Без cookies /, /login, /requests/new и /requests/:id вернули HTTP 200 с приложением, без ChatGPT gate. Неавторизованный браузер показывает форму входа, затем регистрации; приватные заявки не открываются без Supabase-сессии. HTTP 200 вложенного SPA-маршрута не доказывает успешное чтение заявки — доступ определяет Auth/RLS.

Чистая публичная сессия и ширина 375 px проверены инструментом браузера. Физический смартфон и новый полный signup с письмом ещё не проверены.

## Актуальные оставшиеся обязательные действия

Пользователь подтвердил ранее перечисленные signup, пустую форму, совместный поиск/фильтр, двойной клик и мобильный сценарий. Следующие старые пункты закрыты его ручной проверкой. Новое блокирующее требование — доступ из РФ без VPN: на chatgpt.site не выполнено. Подготовлено размещение Amvera; создание проекта и тариф ещё не согласованы. После размещения нужно проверить новый домен, ресурсы и Supabase из РФ и другой страны.
