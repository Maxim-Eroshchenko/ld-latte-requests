## Защита Supabase

### Дополнительная production-проверка потери связи

4 ноября 2026 года, 19:37 UTC, выполнен отдельный автоматический браузерный прогон на Amvera с настоящим Supabase: PASS, код завершения 0. Ответы API не подменялись. Через Playwright context.setOffline отключалась сеть только тестового браузера; независимый клиент с обычными правами тестового пользователя проверял фактические строки базы.

При создании и редактировании запросы POST/PATCH завершились net::ERR_INTERNET_DISCONNECTED. Показано сообщение «Не удалось связаться с сервером. Проверьте интернет и повторите попытку.»; поля сохранены, ложного успеха нет, форма разблокирована, база не изменена. После восстановления сети повторные сохранения получили POST 201 и PATCH 200. В базе ровно одна тестовая заявка, изменения доступны после обновления страницы. UUID оставленной тестовой записи: de3a2340-dddc-44f3-8dbe-e1d2a995631a.

Локальные доказательства (исключены из Git): test-results/production-network/result.json, create-offline.png и edit-offline.png; сценарий test-results/production-network-check.mjs. Проверка подтверждает потерю соединения, но не отдельный реальный HTTP 500 облачного сервиса. Код приложения и настройки Supabase не изменялись.

Ранее npm run test:rls фактически завершился с PASS и кодом 0: A/B читают и меняют свои заявки; прямой чужой SELECT/UPDATE не даёт доступа; подмена user_id при INSERT/UPDATE запрещена; Новая назначается при создании; недопустимые поля и анонимный доступ отклоняются. Проверка не повторялась без причины.

Отдельный запрос pg_class для relrowsecurity/relforcerowsecurity через Supabase MCP вернул Unknown tool. Флаг не прочитан Codex напрямую; включение RLS сообщено пользователем, а реальное поведение изоляции подтверждено API. В исходной миграции RLS включён и forced.

В текущих файлах и всей доступной истории Git не найдены секретные токены, service_role JWT, приватные ключи и фактические пароли тестовых A/B. .env.local/.env.rls и артефакты не отслеживаются. В production-сборке не найдены secret key и пароли A/B. Публичный Supabase publishable key допустим в браузере.
