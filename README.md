# LD LATTE — заявки на автоматизацию

Веб-сервис на русском языке: регистрация и вход, собственные заявки, редактирование, статусы, поиск и фильтрация. Авторизация и хранение данных — Supabase.

- Приложение: https://ld-latte-requests-m-a-x-i-m.msk1.amvera.tech
- Исходный код: https://github.com/Maxim-Eroshchenko/ld-latte-requests
- Оба адреса публичные. Для приложения не требуется аккаунт ChatGPT; для заявок нужен собственный аккаунт Supabase Auth, создаваемый через форму регистрации.
- Существующие заявки других пользователей недоступны. Тестовые пароли проверяющему не передаются.

## Стек и запуск

React 19, TypeScript, Vite, React Router, Supabase JS, React Hook Form, Zod, обычный адаптивный CSS и Lucide. Для проверки используются Vitest, React Testing Library, Playwright и PostgreSQL/PGlite.

Нужны Node.js 22.12+ (рекомендуется Node 24 LTS) и npm.

```powershell
git clone https://github.com/Maxim-Eroshchenko/ld-latte-requests.git
cd ld-latte-requests
npm ci
Copy-Item .env.example .env.local
```

Локально заполните .env.local:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_KEY
```

Для браузера используйте публичный publishable key. Имя переменной ANON_KEY сохранено для совместимости; legacy anon также поддерживается. Пароль БД, service_role и secret key здесь не нужны и не должны попадать в VITE-переменные.

```powershell
npm run dev
```

Откройте http://127.0.0.1:5173. После изменения env перезапустите сервер. Без публичного ключа показывается инструкция настройки.

## Supabase и база

Текущий проект: LD LATTE Development / ld-latte-requests, ref rvfunzjedtcnrpvpsajj. Пользователь сообщил о созданной таблице и трёх RLS-политиках; реальные операции и изоляция API проверены. Повторно миграцию в текущем проекте не запускайте.

Для новой базы следуйте [SUPABASE_SETUP.md](SUPABASE_SETUP.md). Исходная миграция: supabase/migrations/202611040001_requests.sql. Она создаёт UUID/FK, CHECK, индексы, значения по умолчанию, updated_at-триггер, RLS SELECT/INSERT/UPDATE и ограничения записи по колонкам. Владельца и начальный статус назначает база.

Для production в Supabase URL Configuration:

- Site URL: https://ld-latte-requests-m-a-x-i-m.msk1.amvera.tech
- Redirect URL: https://ld-latte-requests-m-a-x-i-m.msk1.amvera.tech/requests
- Локальный Redirect URL: http://127.0.0.1:5173/**

Настройки Amvera показаны на снимке пользователя; прежний Redirect URL Sites сохранён. Подтверждение email не отключалось. Свежая регистрация с письмом проверена пользователем на прежнем публичном домене; на новом домене отдельно не повторялась.

## Архитектура и ограничения

- src/App.tsx — страницы и защищённые маршруты.
- src/hooks/useAuth.tsx — сессия SDK и события авторизации.
- src/components/RequestForm.tsx — валидация, ref-замок параллельных отправок, ожидание и повтор после ошибки.
- src/lib/requests.ts — запросы с явным набором разрешённых полей; после сохранения список читается заново.
- src/lib/model.ts — категории, статусы, валидация и совместный поиск/фильтр.
- supabase/ — воспроизводимая схема и проверка SQL Editor с откатом.

Ограничения: без пагинации, last-write-wins при одновременном редактировании, нет серверного ключа идемпотентности после потери ответа. Подробности — [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

Результат — dist. Обе VITE-переменные должны быть доступны во время сборки; в статическом приложении они не подставляются после публикации.

Основная публикация работает на Amvera с подготовленным кодом 823e55d. Последующие изменения документов не требуют пересборки приложения. Прежняя публикация Sites (версия 1, код 0d3257ce779b76a0c1ea76944d9e42dffdbbecfb) сохранена по адресу https://ld-latte-requests.olivecaribou.chatgpt.site, но возвращает 403 из проверенных сетей РФ и не используется как основная ссылка сдачи.

Запасной вариант — Vercel: импортировать этот репозиторий, выбрать Vite, команда npm run build, output dist, задать две VITE-переменные и добавить новый домен в Supabase URL Configuration. vercel.json уже содержит SPA rewrite. Для Netlify подготовлен public/_redirects. Доступность любого запасного хостинга из РФ требует отдельной проверки.

## Размещение на Amvera

Подготовлен amvera.yaml: Node.js 24 / toolchain npm, сборка npm run build, запуск server.mjs на порту 80. В runtime переносятся только dist и server.mjs. Новый сервер использует только стандартную библиотеку Node.js; установка runtime-зависимостей и перенос базы не нужны.

Amvera не передаёт переменные панели в фазу сборки. Поэтому /runtime-config.js при запуске отдаёт только VITE_SUPABASE_URL и публичный VITE_SUPABASE_ANON_KEY. Клиент читает их перед инициализацией SDK; dev/Vercel/Sites сохраняют поддержку обычных build-time VITE-переменных. Secret/service_role ключи сервер отклоняет.

Порядок воспроизведения размещения в новом проекте:

1. Создать отдельное приложение ld-latte-requests в регионе Москва после согласования тарифа. Не менять существующие проекты бота и прокси.
2. Загрузить main этого репозитория в новый проект Amvera. Использовать конфигурацию из amvera.yaml, а не Node.JS Browser.
3. В разделе Переменные задать VITE_SUPABASE_URL=https://rvfunzjedtcnrpvpsajj.supabase.co и VITE_SUPABASE_ANON_KEY с тем же публичным ключом, что в .env.local. Пароли A/B, secret key, service_role и .env.rls не загружать.
4. Выполнить сборку/запуск. После изменения переменных перезапускать приложение. В журналах не должно быть ошибок конфигурации; выдача /runtime-config.js не кешируется.
5. Получить HTTPS-домен Amvera и добавить его как Site URL и <новый_адрес>/requests как Redirect URL в Supabase. Старые разрешённые Redirect URL можно сохранить.
6. Проверить главную страницу, JS/CSS, прямые вложенные маршруты и регистрацию/вход/заявки из РФ без VPN и из зарубежного узла. Только затем заменить основную ссылку сдачи.

Подготовка проверена локально: сборка без встроенного URL/ключа успешна, 8 unit/component и 2 HTTP/config-теста прошли, 6 браузерных E2E с подменой Supabase прошли повторно. Пользователь создал отдельный проект Amvera в Москве, выбрал тариф «Начальный плюс» и запустил сборку. Снимок панели подтверждает статус «Запущено» и сервер на порту 80. Главная, вложенные маршруты, JS/CSS и публичная runtime-конфигурация ответили 200; работа без VPN подтверждена пользователем и региональными HTTP-проверками. Существующие проекты бота и прокси не изменялись. Тариф и сборки расходуют общий баланс Amvera.

Документация: [Node.JS Server](https://docs.amvera.ru/applications/environments/nodejs-server.html), [переменные](https://docs.amvera.ru/applications/configuration/variables.html).
