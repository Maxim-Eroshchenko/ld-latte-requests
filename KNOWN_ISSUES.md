# Известные ограничения

1. **Supabase MCP недоступен, но реальный клиентский API проверен.** Интеграция возвращает Unknown tool; пользователь настроил схему и публичный ключ. Реальные операции проверены в браузере, `npm run test:rls` с A/B завершился с PASS и кодом 0. Это не полный аудит всех настроек проекта. Миграция повторно не применялась.
2. **Публикация готовится через Sites.** GitHub main подтверждён на исходном коммите 5ea38c4; более поздние изменения нужно синхронизировать. Sites использует отдельный репозиторий публикации. Новый сайт доступен только владельцу; доступ проверяющего и production email redirect требуют проверки перед сдачей. Успех публикации подтверждается отдельно платформой.
3. **Список без пагинации.** Поиск и статистика работают по загруженным строкам; действует лимит ответа Supabase (обычно 1000). Для большого объёма нужны серверный поиск, пагинация и отдельные агрегаты. Текущая реализация рассчитана на небольшой внутренний сервис.
4. **Параллельная работа из разных вкладок.** Последняя успешная запись заменяет поля; нет контроля версий или Realtime. На странице списка данные обновляются при её открытии/возврате после сохранения и перезагрузке.
5. **Повтор после неоднозначного сетевого сбоя.** Параллельная отправка одного экземпляра формы заблокирована и протестирована. Если сервер создал запись, а ответ потерялся, новая ручная попытка может создать вторую запись: серверного ключа идемпотентности нет. Сначала проверьте список. Повторные параллельные вызовы обработчика в обычном сценарии не создают второй запрос.
6. **Границы браузерной проверки.** Протестирован Chromium на 1440×1000 и 375×812, визуально просмотрены снимки. Safari, Firefox и физические устройства не проверялись. Базовая доступность предусмотрена (labels, focus, клавиатура, ошибки, live status); полного WCAG-аудита не было.
7. **Зависимости и окружение.** Google Fonts загружается извне; без доступа используется системный шрифт. При сборке есть безвредные предупреждения Rollup об аннотациях стороннего Zod. Проверки проведены на Windows и Node 25.8.2; для установки рекомендуется Node 24 LTS. Аудит показывает состояние известных уязвимостей на дату проверки, а не гарантирует их отсутствие в будущем.

Фактически прошли: TypeScript, ESLint, production-сборка, 8 unit/component-тестов, 22 локальные PostgreSQL-проверки (включая выполнение сценария SQL Editor и откат его записей) и 6 браузерных тестов с подменой HTTP API. Реальный облачный API проверен с A/B; production-домен и его email redirect ещё требуют проверки после публикации. Не утверждается полное отсутствие ошибок за пределами этих проверок.
